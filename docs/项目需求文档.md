## 已确认事项

> 以下事项已经客户确认，纳入最终版。

| # | 问题 | 确认方案 |
|---|------|----------|
| 1 | 客户信息不完整（缺姓名/缺联系方式/虚假信息）怎么判别有效？ | **电话号码作为唯一有效性标准** — 有电话号码即视为有效线索，可录入数据库并分配给业务；无联系方式的仅作为咨询记录，不进入CRM |

| 3 | 心理测评具体内容和标准？ | 一期先用**AI对话式情绪评估**（由学生Agent在对话中分析情绪状态，输出情绪标签+评分），不做标准化量表；二期再引入专业心理测评量表 |
| 4 | "更进一步"在学生界面换名称？ | 改为**"更多服务"**，避免业务术语暴露给学生 |
| 5 | 人事角色一期怎么处理？ | 一期**并入经理/总裁**（MANAGER角色），二期拆分为独立人事模块，届时人事无法查看客户信息和经营状况 |
| 6 | 客户状态机 6 态流转约束（v6.2.0） | **写死枚举 + 硬编码转换表**（A方案），状态：新录入→跟进中→意向强烈→已签约→已入学→已流失；已签约/已入学也可流失；已流失可回流跟进中 |
| 7 | 心理关怀待办标记实现方式（v6.2.0） | **复用 student_psych_alert 表**（A方案），加 handled_action + handled_at 字段，形成"预警→处理→关怀记录"闭环 |
| 8 | 日报补报申请审批类型（v6.2.0） | **复用现有 late_report**（A方案），次日 0 点前免审批补提，过后需经理审批 |
| 9 | 客户再分配是否走审批（v6.2.0） | **MANAGER 直接生效，不走审批**（A方案），但必须写操作日志 + 发事件通知新 owner |

| 11 | Excel 导出格式（v6.2.0） | **CSV 同步导出**（A方案），零依赖，Excel/WPS 可直接打开；数据量小同步返回 |

## 一、项目概述

### 1.1 项目背景

广东省教育服务有限公司（简称"粤教服务"）创办于1981年，2024年3月划转至广东教育国际交流服务中心有限公司（简称"粤教国际"）。公司主营业务包括国际教育、智慧教育、素质教育和实体教育。

核心业务线：
- **德国双元制职业教育项目**：中德精英人才共建计划
- **新加坡国际本硕升学项目**：定向培养联合办学项目
- **国际留学项目**：全球数百所院校合作
- **国际研学项目**：面向中小学生、高职高专及大学生

### 1.2 项目目标

构建一个智能化的教育服务管理平台，覆盖从**意向客户获取 → 客户研判 → 留学申请 → 学生服务**的完整业务闭环，集成三大AI Agent能力：

1. **智能客服Agent** — 公开主页置顶，主动接待访客，采集意向客户信息，7大场景智能应答
2. **企业智能助手Agent** — 员工/管理层端置顶，CRM管理、日报整理、待办提醒、指令式业务处理
3. **学生智能助手Agent** — 留学生端置顶，行政服务、心理关怀、学业追踪、生活支持

### 1.3 用户角色

| 角色 | 编码 | 描述 | 账号来源 | 核心功能 |
|------|------|------|----------|----------|
| 意向客户 | `PROSPECT` | 陌生访客、意向客户，尚未与公司有业务往来，来了解公司业务 | 自行注册（功能权限需由员工开通） | 浏览课程/活动、提交咨询、活动报名 |
| 留学生 | `STUDENT` | 公司核心服务对象，由意向客户转化而来 | 员工申请 → 经理审批后转化 | 请假申请、考务查询、心理关怀、反馈提交、课程报名、进度追踪、生活支持 |
| 员工 | `EMPLOYEE` | 公司工作人员 | 管理层创建 | CRM录入/跟进（支持文字/PDF/照片/Word/Excel多格式）、代客户申请留学生、审批学生流程、口述日报、成绩录入、待办处理 |
| 管理层 | `MANAGER` | 公司管理人员（含经理/总裁） | 系统管理员创建（测试用），或由其他管理层创建 | 全部客户查询、经营看板、智能报告、审批员工流程、员工管理、权限配置 |

**角色说明**：
- **系统管理员账号**：保留一个测试用系统管理员账号（种子数据初始化），仅用于开发和测试环境的系统配置，**不参与正式业务流程**
- **一期不区分子角色**：经理和总裁统一为 MANAGER 角色，均可查看全部客户和经营数据；人事功能并入 MANAGER
- **二期拆分为3个独立角色**：
  - **人事（HR）**：独立角色，可管理员工但无法查看客户信息和经营状况
  - **经理（MANAGER_DIRECTOR）**：只能看到归属于自己下属的员工客户信息和自己直接录入的客户信息，不能看到公司所有客户
  - **总裁（MANAGER_PRESIDENT）**：可看到公司所有客户信息，拥有管理层最高权限

**角色业务流程**：

```
客户信息来源（三渠道）：
  1. 意向客户自行注册（公开主页，填写必填+选填信息）
  2. 员工录入客户信息（支持文字输入、PDF、照片、Word、Excel等多格式）
  3. 管理层录入客户信息（同上，多格式录入）

客户重复处理：按电话号码去重，先录入的员工获得跟进权；管理层可变更跟进员工

意向客户注册/录入 → 员工审核并开通功能权限
    → 员工申请将意向客户转化为留学生 → 经理审批
    → 留学生使用平台服务（请假、考务、反馈等）
    → 负责的员工审批留学生提交的流程

员工数据隔离：普通员工只能看到自己名下的客户信息，防止业务恶性竞争
管理层权限由系统管理员逐人配置（JSON权限列表）
```

5. 活动与讲座报名（**需注册登录后才可报名**，未登录跳转登录页，登录后跳回继续报名）
6. 常见问题自助解答
7. 日常闲聊互动
   - 支持年轻化人设和个性化推荐

#### 2.1.3 用户登录/注册模块
- **注册必填信息**：姓名、性别、年龄、联系方式、学历
- **注册选填信息**：家庭经济状况、职业需求、德语能力
- **注册后状态**：待开通（需员工审核开通功能权限）
- **登录后权限**：浏览课程/活动、提交咨询、活动报名

#### 2.1.4 智能客服Agent窗口（置顶，随时等待客户调用）
- **窗口置顶**：无论用户在哪个页面，Agent窗口始终可见
- **主动咨询**：Agent主动询问客户感兴趣的内容，判断客户是否为意向客户
- **信息采集**：在咨询过程中自然了解客户信息（姓名、性别、年龄、联系方式、学历、家庭经济基础、职业需求、德语能力等）
- **对话历史保留**：同一用户反复沟通不重复建立信息，每次都更新信息即可
- **信息录入**：对话中透露的客户信息自动提取、过滤、整理后录入数据库

## 三、功能模块详细设计

### 3.1 意向客户交互模块

#### 3.1.1 页面交互
- 公开主页浏览（公司介绍、业务展示、课程/活动）
- 与智能客服Agent对话（信息采集、业务咨询）
- 注册账号（必填+选填字段）
- 活动报名（需登录后）

#### 3.1.2 业务流程
```
1. 意向客户访问公开主页
2. 与智能客服Agent对话（Agent主动采集信息）
3. 意向客户自行注册（填写必填+选填信息）
   → 账号状态为"待开通"
4. 员工审核并开通功能权限
5. 员工将意向客户转化为留学生（需经理审批）
   → user_type: PROSPECT → STUDENT
6. 留学生使用平台服务
7. 负责的员工审批留学生提交的流程
```

### 3.2 客户信息采集与研判模块

#### 3.2.1 三渠道信息采集

**渠道一：意向客户自行注册**
- 注册时提交的必填信息（姓名、性别、年龄、联系方式、学历）
- 注册时提交的选填信息（家庭经济状况、职业需求、德语能力）
- 与智能客服Agent对话中透露的信息

**渠道二：员工直接提交**
- 文字输入（手动填写客户信息表单）
- 文件上传（PDF、照片、Word、Excel）
- 与企业智能助手Agent对话中录入

**渠道三：管理层直接提交**
- 同员工提交方式（文字/文件/Agent对话）

#### 3.2.2 信息处理流程
```
采集原始信息
  → AI信息提取（从文字/文件中提取结构化字段）
  → 有效性过滤（电话号码为唯一有效性标准，有电话号码=有效线索）
  → 客户信息整理（填充CRM字段）
  → 画像匹配（根据《用户画像研判规则》计算匹配度）
  → 录入数据库
  → 输出研判结果（匹配度评分、推荐产品）
```

#### 3.2.3 有效性判断规则
- **有效线索**：包含电话号码的信息 → 录入CRM，分配给录入员工跟进
- **无效信息**：无联系方式 → 仅记录为咨询日志，不进入CRM
- **虚假信息**：AI辅助检测明显矛盾信息（如年龄15岁但学历为博士），标记为"待核实"
- **不完整信息**：仅有电话号码 → 录入CRM，标记为"信息待补充"

#### 3.2.4 客户重复处理
- 按**电话号码**去重
- 先录入的员工获得该客户的跟进权
- 管理层可在CRM中变更跟进客户归属的员工

#### 3.2.5 研判结果展示
- 员工可在CRM客户详情页查看研判结果（匹配度评分、推荐产品）
- 管理层可查看全部客户的研判结果
- 意向客户和留学生不可查看研判结果

### 3.3 留学生管理模块

> 支持两种方式操作：页面直接操作 + 学生智能助手Agent对话操作

#### 3.3.1 行政服务（请假）
```
流程：
1. 留学生在页面提交或通过Agent对话提交请假申请
2. 系统创建审批流程，写入数据库
3. 负责该学生的员工收到审批通知
4. 员工审批（通过/驳回），写入数据库
5. 审批结果通过站内消息+Agent推送给学生
```

> **v6.8.2 审批人解析规则（实装确认）**：学生提交服务单时，系统自动解析审批人=该学生关联客户（`Customer.sys_user_id == 学生ID`）的负责员工（`owner_employee_id`）；学生尚无关联客户/负责员工时审批人留空，由员工端任意员工/管理层兜底认领审批。审批严格校验：已指定审批人时非本人操作返回 40301。

#### 3.3.2 心理关怀（情绪疏导+预警）
```
流程：
1. 学生与Agent对话，Agent进行情绪疏导
2. AI在对话中分析情绪状态（一期：对话式评估，不做标准化量表）
3. 输出情绪标签+评分，写入心理画像表
4. 若情绪评分低于阈值，触发预警（通知负责员工）
5. 二期引入专业心理测评量表
```

#### 3.3.3 售后反馈
```
流程：
1. 学生在页面提交或通过Agent对话提交反馈工单
2. 系统创建工单，状态为"待处理"
3. 负责员工查看并处理
4. 处理结果反馈给学生
```

#### 3.3.4 学业考务
```
功能：
- DDL提醒（论文提交、作业截止等）
- 考试安排查看
- 成绩查看
- 智能提醒（提前N天推送提醒）
```

#### 3.3.5 进度追踪
```
功能：
- 留学申请各阶段进度查看
  - 材料审核 → 申请提交 → 收到Offer → 签证办理 → 行前准备 → 已入学
- 每个阶段的备注和更新时间
- 由负责员工在后台更新进度
```

> **实现归属（2026-10-17 需求对齐确认）**：进度追踪的员工端更新接口与学生端查看接口均由 **M4 学生模块统一实现**（表 student_application_progress 属 M4 模型，避免 M3 跨模块操作 M4 表）；员工端更新接口可挂 `/employee` 前缀满足前端动线，权限 EMPLOYEE/MANAGER，且仅负责该学生的员工可更新。

#### 3.3.6 生活支持
```
功能：
- 海外生活常见问题解答（Agent基于知识库回答）
- 紧急联系方式
- 住宿、交通、生活指南
```

#### 3.3.7 更多服务（增值转化）
```
功能：
- 课程升级推荐
- 新项目推荐
- 背景提升机会
- 学业规划建议
注意：此模块面向学生，不使用"增值转化"等业务术语
```

## 四、智能Agent设计

### 4.1 智能客服Agent（公开主页）

**部署位置**：公开主页右下角置顶，所有页面可见

**7大场景**：
1. 公司信息咨询
2. 公司业务查询
3. 海外留学政策查询
4. 课程与项目推荐
5. 活动与讲座报名
6. 常见问题自助解答
7. 日常闲聊互动（年轻化人设+个性化推荐）

**核心策略**：
- **主动出击**：Agent主动询问客户感兴趣的内容，判断是否为意向客户
- **信息采集**：在对话中自然引导客户提供信息（姓名、性别、年龄、联系方式、学历、家庭经济基础、职业需求、德语能力）
- **信息更新**：同一用户反复沟通不重复建立信息，每次对话后更新已有信息
- **知识库驱动**：基于RAG知识库回答（公司信息、业务资料、FAQ、政策指南）

### 4.2 企业智能助手Agent（员工/管理层端）

**部署位置**：员工端右下角置顶，所有页面可见

**核心策略**：
- **主动提醒**：提醒员工未达成任务、待跟进客户、待审批事项
- **权限感知**：根据当前用户角色和权限，开放不同的查询和操作能力
- **数据隔离**：普通员工只能查询自己名下的客户；管理层可查询全域
- **指令执行**：支持指令式业务处理（如"帮我给张三添加跟进记录"），执行前需二次确认
- **日报整理**：员工口述工作内容，AI自动整理成结构化日报格式

### 4.3 学生智能助手Agent（留学生端）

**部署位置**：留学生端右下角置顶，所有页面可见

**核心策略**：
- **心理关怀**：情绪疏导、陪伴式对话
- **提示词限制预期**：
  - 不给出超出服务范围的承诺
  - 不提供医疗级心理建议
  - 不承诺退费、转学等重大决定
  - 遇到严重心理问题，引导学生联系专业心理咨询师
- **主动推送**：学生登录后，Agent主动推送待办事项、DDL提醒、审批结果
- **行政代办**：帮助学生提交请假、查询考务等

### 10.1 认证机制

**Token生成**：
```python
from datetime import datetime, timedelta
from jose import jwt
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)

def get_password_hash(password: str) -> str:
    return pwd_context.hash(password)

def create_access_token(data: dict) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=1440)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm="HS256")
```

### 11.3 API请求封装

```typescript
import axios, { AxiosInstance } from 'axios';
import { ElMessage } from 'element-plus';
import { useUserStore } from '@/stores/user';

const service: AxiosInstance = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL || '/api/v1',
    timeout: 30000,
});

service.interceptors.request.use((config) => {
    const userStore = useUserStore();
    if (userStore.token) {
        config.headers.Authorization = `Bearer ${userStore.token}`;
    }
    return config;
});

service.interceptors.response.use(
    (response) => {
        const res = response.data;
        if (res.code !== 200) {
            ElMessage.error(res.message || '请求失败');
            if (res.code === 40101) {
                const userStore = useUserStore();
                userStore.logout();
                window.location.href = '/login';
            }
            return Promise.reject(new Error(res.message));
        }
        return res;
    },
    (error) => {
        ElMessage.error(error.message || '网络错误');
        return Promise.reject(error);
    }
);

export default service;
```

```python
import httpx

class AIService:
    def __init__(self):
        self.dify_base_url = settings.DIFY_BASE_URL
        self.dify_api_key = settings.DIFY_API_KEY

    async def chat(self, agent_key: str, message: str,
                   conversation_id: str = None, user_id: int = None) -> dict:
        async with httpx.AsyncClient() as client:
            response = await client.post(
                f"{self.dify_base_url}/chat-messages",
                headers={
                    "Authorization": f"Bearer {agent_key}",
                    "Content-Type": "application/json"
                },
                json={
                    "inputs": {},
                    "query": message,
                    "response_mode": "blocking",
                    "conversation_id": conversation_id or "",
                    "user": str(user_id) if user_id else "anonymous"
                }
            )
            return response.json()
```

## 十八、智能报告模块（M5）功能说明（v2.8.7 补录）

> 依《一期指标口径表V1》（`promts/智能报告/report_package/02_一期指标口径表V1.md`，权威口径）与后端交付说明 V1 补录；此前本文档仅有导航项与权限码、无功能章节。

### 18.1 五类报告

| report_type（以代码为准） | 名称 | 周期 | 核心指标 |
|---|---|---|---|
| `customer_analysis` | 客户经营分析报告 | 周/月 | 期末 6 态总览、期末意向/成交/流失、本期新增与去向、新加坡/德国项目画像三分类 |
| `daily_report_summary` | 员工日报汇总 | 日 | 按日应提交/已提交/未提交（在职员工×周一至周五） |
| `weekly_report_summary` | 员工周报汇总 | 周 | 全周人次、每日明细、部门汇总 |
| `psych_weekly` | 学生心理健康周报 | 周 | 覆盖学生数（去重）、高/中/低风险分布 |
| `complaint_weekly` | 投诉处理周报 | 周 | 新增/解决/未解决/超7天未解决、首次响应时长与未响应、满意度、特别案例（已复核） |

### 18.2 生成与版本

- **手动生成**（一期不做调度/订阅）：`POST /api/v1/reports/generate`，周期缺省取参考周期
- **版本规则**：同类型同周期重复生成保留旧版本、版本号递增；列表默认折叠为最新版本
- **状态**：一期同步生成，落库即 `completed`；`failed`+`error_message` 为失败态预留

### 18.3 权限与下钻

- 报告列表/生成/详情/客户下钻/特别案例/PDF 下载：**MANAGER/ADMIN**
- 心理个案 `psych_cases`：MANAGER/ADMIN 看全部（授权范围二期随角色拆分细化）、EMPLOYEE 仅看自己负责、其余角色 403
- 投诉特别案例：仅返回已人工复核（approved），只含案例编号/负责人/进度

### 18.4 导出与脱敏

- `GET /reports/{id}/download` 导出脱敏 PDF（reportlab）：仅聚合指标与 AI 文字，不含姓名/联系方式/原文/处理详情/心理反馈/未复核案例
- 一期不做 Word/Excel 导出

### 18.5 数据来源现状（如实标注，v6.9.0 更新）

- **模拟数据闭环：已完成**（`data_source_status=mock`，参考周期 2026-10-12~10-19）
