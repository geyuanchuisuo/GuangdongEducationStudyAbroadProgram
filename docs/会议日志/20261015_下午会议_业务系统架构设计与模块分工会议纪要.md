## 一、业务模块划分与功能定义

### 1.1 核心模块构成

确定五大核心模块，并整合至**统一前端对话入口**，实现数据资产转化：

| 序号 | 模块名称 | 定位 |
| --- | --- | --- |
| 1 | 客户研判 | 潜在客户筛选 |
| 2 | 客服推荐 | 引导转化 |
| 3 | 企业智能助手 | 业务管理（员工端） |
| 4 | 学生智能助手 | 学生服务端 |
| 5 | 智能报告 | 经营分析数据输出 |

### 1.2 数据流转逻辑

| 环节 | 模块 | 动作 |
| --- | --- | --- |
| ① | 客户研判 | 筛选潜在客户 |
| ② | 客服推荐 | 引导转化 |
| ③ | 企业 / 学生智能助手 | 进行管理 |
| ④ | 智能报告 | 输出经营分析数据 |

```
客户研判  →  客服推荐  →  企业 / 学生智能助手  →  智能报告
```

### 1.3 客户研判与信息采集

**信息来源与录入流程**

- 意向客户自行注册（必填字段）；
- 员工录入（销售 / 管理层）；
- 客服交互补充；
- 重复客户按**录入时间**归属，并支持**管理层调整**。

> **补充确认**：重复客户按「最早录入时间」优先归属，管理层可在系统中手动调整归属人。

**有效判定标准**

- 电话号码作为核心有效标识（需校验）；
- 缺失信息通过客服交互补全。

> **补充确认**：号码校验采用短信验证码方式，通过验证方计为有效客户。

### 1.4 模块功能细化

#### （1）企业智能助手

员工端功能包含：

- 客户信息管理；
- 工单处理；
- 学生请假审批等。

支持**三级权限隔离**：普通员工 / 经理 / 总裁。

> **补充确认**：一期三级权限从简，仅做身份区分与基本隔离，不细分权限矩阵，细化留至二期。

#### （2）学生智能助手

- 考务进度查询；
- 心理测评：一期采用情绪评估，二期引入专业量表；
- 升学服务等功能。

> **补充确认**：一期情绪评估只记录、不评分，不做量表分值与心理诊断结论；评估结果以去标识化的聚合口径（如提交量、情绪标签分布）纳入智能报告统计，不做个体名单呈现。
>
> **待明确**：「只记录不评分」与「纳入智能报告统计」之间需约定统一统计口径；学生心理数据进入管理层报告前，须完成授权与脱敏。

#### （3）智能报告

- 依赖前序模块数据生成经营分析报告；
- 管理层权限分级查看。

> **待明确**：
> - 报名数据与客户转化（意向客户 → 成交 / 转留学生）是否自动联动，还是仅作记录；
> - 审批驳回后的处理（退回修改 / 重新发起）与审批链是否允许加签。

**二期扩展方向**

1. 管理层角色拆分（总裁 / 经理 / 人事）；
2. 数据架构优化；
3. 心理测评量化升级。

### 2.2 技术实现策略

**前端架构**

- 统一主页面导航入口；
- 按角色权限展示不同功能模块；
- 区分登录前 / 登录后状态。

**数据互通机制**

- 学生投诉 / 请假数据经企业端审批后**双向同步**；
- 使用数据库作为核心数据流转通道。

### C.1 未决事项

| 编号 | 未决事项 | 影响 |
| --- | --- | --- |
| O1 | 客户研判、客服推荐、智能报告三个模块的负责人 | 五大模块中有三个无归属，无法排期与追责 |
| O2 | 现有技术栈的具体框架 / 数据库 / 部署方式 | 影响数据架构设计与前端方案 |
| O3 | 一期功能点清单（需求表格定稿） | 「完整度 100%」缺少判定基线 |
| O4 | 一期「情绪评估」与智能报告的统计口径 | 不评分则报告中缺可比较指标 |
| O5 | 活动报名与客户转化是否自动联动 | 影响客户研判的数据来源链路 |
| O6 | 审批驳回后的处理与能否加签 | 影响 OA 审批流程实现 |

### C.2 风险提示

1. **无时间约束 + 100% 完整度要求**：验收标准刚性而工期开放，容易在验收环节产生分歧，建议先给出里程碑。
2. **三个模块无负责人**：客户研判与客服推荐是数据流上游，缺人会导致下游模块无数据可用。
3. **合规风险自留**：号码、未成年人个人信息与情绪记录同时进入经营分析报告，后续补做授权、脱敏与留存策略的改造成本显著高于一期同步设计。
4. **「禁止模糊实现」的落点**：该要求只在需求表格定稿后才可执行判定，表格未定前建议先冻结一期功能边界。
