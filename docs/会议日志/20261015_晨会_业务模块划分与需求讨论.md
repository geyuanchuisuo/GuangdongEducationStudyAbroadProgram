# 业务模块划分与需求讨论
## 1. 业务模块划分与功能细化
1. 模块划分标准：根据业务场景将系统划分为五个核心模块，分别为客户研判、客户模块、企业智能助手、学生智能助手、智能报告，每个模块需明确对应用户角色及业务流转逻辑。

2. 模块功能细化：客户研判模块需解决PDF/Excel字段检索稳定性、规则动态配置、高价值信息误判人工兜底三大难点；客服认证模块需覆盖公司信息展示、政策解读、个性化课程推荐及客户线索跟进；企业智能助手需实现客户管理、日报汇总、组织架构查询及学生业务分管功能。

3. 智能报告模块定位：核心价值在于通过数据整合发现业务规律（如客户转化渠道分析、投诉类型统计），而非单纯图表展示，需与管理层决策需求直接关联。

## 2. 用户角色与权限管理
1. 用户角色定义：系统存在访客、学生、员工、管理层、系统管理员五类用户，其中系统管理员权限需明确是否包含公司内部资料访问权限。

2. 权限分配逻辑：管理层可查看整体业务状态（如员工工作状态、学生心理状态），员工仅能操作客户状态维护、日志记录等职责范围内功能，学生模块需实现请假审批、心理关怀等闭环服务。

## 3. 需求文档编写分工
1. 文档内容要求：每人需独立完成模块需求报告，内容包含业务痛点、功能点说明、业务流程图示三要素，建议采用表格形式横向对比模块差异。

2. 原型设计规范：产品原型需体现核心业务流转路径（如意向客户→注册→权限开通流程），但暂不涉及具体技术实现细节，优先保证业务需求可视化。

## 4. 后续工作安排
1. 阶段划分原则：采用分阶段开发策略，第一期聚焦基础功能实现（如客户信息必填字段定义、核心业务流程贯通），第二期进行功能优化扩展。

2. 交付时间节点：所有成员需在当天完成各自负责模块的需求文档初稿，次日进行原型设计讨论及技术架构对接。

3. 技术协作机制：前端与后端需统一接口规范（如请求体格式），确保同步开发时的数据交互一致性，具体技术选型待需求确认后讨论。
