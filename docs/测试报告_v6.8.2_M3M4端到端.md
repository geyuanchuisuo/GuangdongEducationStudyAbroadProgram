## 三、缺陷记录（7 项，均已修复并回归验证）

| # | 端点 | 缺陷 | 根因 | 修复 | 验证 |
|---|------|------|------|------|------|
| 1 | GET /student/academic | 50001 | `datetime.now(timezone.utc)`（aware）与 MySQL 读回 naive DATETIME Python 侧比较 → TypeError | 改 naive `datetime.now()` | ✅ R3 |
| 2 | GET /student/reminders | 50001 | 同上（Python 侧减法） | 同上 | ✅ R3 |
| 3 | POST /student/admin-services | 学生请假永远无人可审 | 提交时不设 approver_id，M3 校验 `approver_id != employee_id` 恒 40301 | 提交时解析审批人=负责员工（Customer.owner_employee_id），无则 NULL | ✅ R4 |
| 4 | POST /employee/admin-services/{id}/review | 空审批人无法认领 | 校验无 NULL 兜底分支 | approver_id 为 NULL 时任何员工/管理层可认领 | ✅ R4 |
| 5 | PATCH /employee/customers/{id}/status | 50001 | commit 后读 `customer.updated_at`（已过期）→ 异步上下文 MissingGreenlet | commit 后 `await self.db.refresh(customer)` 再读 | ✅ R2 |
| 6 | GET /operation-logs | 50001（v6.6.0 上线以来） | `_get_service` 构造 `EmployeeService(db)` 缺 4 仓储依赖 | 按 employees.py 同款补全仓储依赖 | ✅ R3 |
| 7 | GET /operation-logs | 50001（⑥修复后暴露的深层缺陷） | OperationLogItem 缺 `from_attributes` → ORM 校验失败 | 加 `model_config = ConfigDict(from_attributes=True)` | ✅ R3 |

> 另：首轮 2 个 "Connection reset by peer" 为 keep-alive 连接复用假象（前一个 500 关闭连接，下一请求撞死连接），非独立缺陷，测试脚本加 `Connection: close` 头消除。

2. **AI 相关端点**均走降级路径（预期行为）：Dify Agent Key 配置后需重测 agent/chat、psych/chat、guide/ask 的真实 AI 链路
