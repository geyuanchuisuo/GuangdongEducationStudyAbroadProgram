## 0. 通用约定

| 项 | 约定 |
|---|---|
| 协议 | HTTP + JSON，内部服务调用，路径前缀 `/internal/reports/`（由各模块自行决定是否复用公开路由） |
| 时间 | naive datetime 表示北京时间；周期为左闭右开 `[start, end)` |
| 鉴权 | 服务间固定 token 或复用 M0 内部网关鉴权，**不得要求用户 token** |
| 语义 | 只读；返回 `data_quality` 或等价状态字段；**缺失必须显式标注，不得返回 0 顶替** |
| 版本 | 返回体带 `schema_version`，字段只增不减；破坏性变更需提前通知 M5 |
| 错误 | 4xx/5xx 之外，允许 200 + `status="unavailable"` 表达「数据不可得」 |

### 5.1 给 M0 的最小补丁（经用户确认：由 M0 负责人实施，M5 不改共用模块）

```python
# backend/app/config.py  —— Settings 内，紧随 DIFY_CUSTOMER_AGENT_KEY
    DIFY_REPORT_AGENT_KEY: str = ""      # v6.11.0：M5 报告专用 Agent（云端 Dify）

# backend/app/services/ai_service.py
class AgentType(str, Enum):
    CUSTOMER = "CUSTOMER"
    EMPLOYEE = "EMPLOYEE"
    STUDENT = "STUDENT"
    REPORT = "REPORT"                    # v6.11.0：报告专用 Agent（M5 使用）

_AGENT_KEY_MAP: dict[AgentType, str] = {
    # …原有三项保持不变…
    AgentType.REPORT: settings.DIFY_REPORT_AGENT_KEY,
}
```

配套：
- `backend/.env`（不入库）设置 `DIFY_BASE_URL=<你的 Dify 实例地址>`（⚠️ 现行基线：本机 `http://localhost:8081`/容器内 `http://dify_nginx`，见 docs/Dify部署与调用指南.md）、`DIFY_REPORT_AGENT_KEY=app-xxx`
- `backend/.env.example` 补一行占位 `DIFY_REPORT_AGENT_KEY=`
- `_AGENT_KEY_MAP` 在模块导入时构建 → **改完需重启后端**
- 该 Agent 需为「聊天助手/Agent」类型并开启 API 访问；提示词要求**只输出 JSON**（M5 已带 `summary/trend/analysis/suggestions` 的结构约束与 schema 校验）

> M5 侧代码已按「探测 `AgentType.REPORT`」实现：M0 登记前 AI 恒为 `unavailable`（不回落、不伪造）；登记 + 配 key 后**无需改 M5 代码即可生效**。

### 5.2 Dify 实例与报告 Agent 实测记录（2026-10-18 / v6.11.1，⚠️ 旧 VM 实例历史记录，现行部署见 docs/Dify部署与调用指南.md）

| 项 | 结果 |
|---|---|
| 实例 | `http://192.168.184.128`（本地 VMware 虚拟机，NAT 网段） |
| 容器内连通性 | ✅ `docker exec edu-backend` 可直连 `192.168.184.128:80` |
| 应用 | **智能报告**，`mode=agent-chat`（Agent 类型） |
| `GET /v1/info` | ✅ 200，name=智能报告，mode=agent-chat |
| `GET /v1/parameters` | ✅ 200 |
| `POST /v1/chat-messages` + `response_mode=blocking` | ❌ **400 `Agent Chat App does not support blocking mode`** |
| `POST /v1/chat-messages` + `response_mode=streaming` | ✅ 200；事件 `agent_thought`×2 / `agent_message`×406~995 / `message_end`×1；耗时 3.6s（客户经营）/ 6.3s（投诉） |
| JSON 契约 | ✅ 两例均 `_parse_json` + `_validate` **PASS**（`summary/trend/analysis/suggestions` 齐全、类型正确） |
| 输出形态风险 | ⚠️ 正文前含 `<think>` 推理块 + `<!--dify-deepseek-reasoning-->` 注释，思考块内可能出现花括号 → M5 已加 `_strip_reasoning()` 加固（v6.11.1，含单测） |
| 数值合规抽查 | ✅ 未自造数字；客户经营例中模型复述了「禁止评价个人绩效」这句话（非绩效评价，属提示词回显） |

**由此产生的两条 M0 决策（二者择一，M5 侧无需改代码）**：

1. **Dify 侧改应用类型**：把「智能报告」从 Agent 改成 **Chatbot（聊天助手）** → 支持 `blocking`，网关现有 `AIService.chat()` 可直接用；
2. **网关侧支持流式**：`ai_service` 已有 `chat_stream()`，为 `AgentType.REPORT` 走 streaming 并在网关内聚合 `agent_message` 分片后返回整段文本（M5 只消费最终 JSON）。

> 现状：M5 探测 `AgentType.REPORT` 不存在 → AI 恒 `unavailable`（符合「不回落、不伪造」）。M0 完成上述任一项 + 配置 `DIFY_REPORT_AGENT_KEY` 后，M5 **无需改代码**即可走真实链路。
