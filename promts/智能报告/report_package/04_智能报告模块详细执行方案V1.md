# 智能报告模块一期详细执行方案 V1

## 一、执行原则

1. 先完成模拟数据闭环，再联调真实模块。
2. 报告逻辑只消费统一的标准化数据，不直接查M1-M4业务表。
3. 程序计算事实指标，AI只做文字归纳和建议。
4. 未确认规则不擅自决定，必须标注待确认。
5. 先完成后端数据和报告内容，再做页面、PDF和AI增强。
6. 每次改动都要有测试和结果记录。

## 二、推荐分工

### Agent A：数据契约与模拟数据
整理统一报告输入结构、模拟数据、预期结果和真实数据转换边界。不得修改业务模块。

### Agent B：报告后端核心
完成报告模型补充、Repository、Service、生成编排、列表、详情、手动生成、版本和状态。先不接真实M1-M4。

### Agent C：指标计算与报告内容
实现客户、员工、心理、投诉四类计算器和报告JSON结构，编写单元测试。禁止在计算器中调用AI。

### Agent D：AI分析与PDF
实现统一AI分析入口、结构化输出、失败降级、PDF汇总导出和心理/投诉脱敏。不得让AI计算核心数字。

### Agent E：前端与权限
实现管理层报告页面、周期选择、报告历史、详情、下钻、PDF下载、角色与个案权限。后端权限必须同步实现。

如果只有一个Agent，必须按上述顺序串行执行；不要同时做所有内容。

## 三、阶段计划

### 阶段0：基线和目录
读取项目AGENTS.md、需求文档、主基线、接口契约、报告提示词和本资料包。确认当前分支和工作区，不覆盖已有功能。

### 阶段1：统一输入和模拟数据
建立四类报告输入结构和模拟提供器。数据包含模拟标记、数据更新时间、周期字段和预期结果。完成客户、员工、心理、投诉边界场景。

### 阶段2：确定性指标
实现周期计算、北京时间、去重、状态分类、画像统计、日报提交统计、心理覆盖统计、投诉时效和满意度统计。先用固定输入做人工核对。

### 阶段3：报告持久化和接口
完成手动生成、生成状态、失败原因、报告列表、详情、版本、历史版本、统一报告内容结构。重复生成不覆盖旧版本。

### 阶段4：权限和下钻
整体报告只给MANAGER；心理员工只看自己负责个案；客户网页下钻按当前报告筛选条件；PDF不得包含客户或心理个人敏感信息；投诉特别案例只能显示已复核内容。

### 阶段5：AI分析
将确定性指标作为AI输入。AI输出摘要、趋势说明、风险提示和建议。对输出做结构校验；失败时保留统计报告并标记AI不可用。

### 阶段6：网页和PDF
管理层可选择报告类型和周期，手动生成、查看历史、查看详情、网页下钻、下载PDF。心理和投诉PDF只保留脱敏汇总。

### 阶段7：测试和交付
运行单元、接口、权限、PDF脱敏、重复生成、模拟数据回归测试。输出变更摘要、已实现范围、待确认项、测试结果和风险说明。

## 四、后续真实模块衔接

M1-M4完成后分别实现数据适配器：客户、员工日报、心理、投诉。适配器将真实查询接口响应转换为阶段1冻结的统一输入结构。只替换提供器和映射，不修改核心指标和报告模板；若字段语义不同，先由模块负责人确认映射。

## 五、验收标准

- 五类报告可用模拟数据手动生成。
- 同一周期重复生成保留版本。
- 客户一期口径全部通过固定样本。
- 日报补交、周末和全周人次正确。
- 心理覆盖和个案权限正确。
- 投诉类型、响应时长、七天未解决、满意度和复核正确。
- AI失败不阻断确定性报告。
- MANAGER权限、EMPLOYEE心理个案权限和其他角色拒绝正确。
- PDF不泄露客户、学生和投诉个人敏感信息。
- 代码、接口、测试和文档符合项目约定。
