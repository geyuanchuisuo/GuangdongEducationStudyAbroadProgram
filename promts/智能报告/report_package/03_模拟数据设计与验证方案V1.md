# 模拟数据设计与验证方案 V1

## 1. 目标

在M1-M4尚未完成时，用虚构数据独立验证M5的统计、报告结构、权限、下钻、PDF和AI降级。模拟数据必须通过统一格式进入报告逻辑，后续只替换数据提供部分。

## 2. 数据分层

### A. 原始模拟记录

模拟客户、状态、研判、日报、组织、心理记录、心理预警、投诉工单、投诉响应、满意度、复核记录。

### B. 统一报告输入

报告逻辑只接受标准化输入，不直接依赖模拟数据文件或其他模块数据库。正式联调时将M1-M4响应转换为同样的输入结构。

### C. 预期结果

每个场景配人工核对结果，测试报告输出是否正确。

## 3. 最低字段建议

### 客户
`customer_id, phone, name, source_channel, first_register_login_at, first_employee_submit_at, status_at_period_end, status_source, latest_assessment_at, sg_conclusion, de_conclusion, owner_employee_id, follow_up_summary`

### 员工和日报
`employee_id, department, employment_status, report_date, submitted_at, content, is_valid`

### 心理
`student_id, record_at, emotion_tag, risk_level, feedback_summary, responsible_employee_id, has_psych_record`

### 投诉
`ticket_id, student_id, feedback_type, submitted_at, first_response_at, resolved_at, status, satisfaction, ai_low_score, ai_high_risk, review_status, reviewer_id, owner_id, progress`

## 4. 必须覆盖的测试场景

### 客户
1. 两个渠道相同手机号，验证去重和最早新增时间。
2. 期末六种状态各有样本。
3. 本期新增客户期末分别为意向、已签约、已入学、已流失，四项合计等于新增数。
4. 回流客户不进入新增。
5. 自动流失与人工流失分开标注。
6. 同时参与新加坡和中德画像统计。
7. 无研判结果进入信息不足，并标注未完成研判。
8. 历史月份使用当前最新画像结果。
9. 期末状态按周期结束结果，画像按最新有效研判结果。
10. 生成同周期第二版，旧版保留。

### 员工
1. 周一至周五各有应交和未交人员。
2. 周末提交不计应交/未交，但内容可进入周报。
3. 周二补交周一日报，归入周一，重新生成可纳入。
4. 同一员工同一天多次修改不重复计数。
5. 多部门有进展、产出、风险和无法归类文本。
6. 上周与本周有持续事项、新风险、已完成协调事项。

### 心理
1. 全体学生中只有部分学生本周有记录。
2. 同一学生多条记录按学生去重。
3. 有高风险记录，模拟即时通知事件但报告只做统计。
4. 管理层可访问授权个案；无负责关系员工被拒绝。
5. PDF不含姓名、联系方式和具体反馈。

### 投诉
1. 投诉、建议、咨询混合，只有投诉计入。
2. 有已响应、未响应、已解决和未解决工单。
3. 恰好7×24小时与超过7×24小时边界。
4. 满意、不满意、无满意度。
5. AI候选未复核不展示为特别案例；复核通过后展示编号、负责人和进度。
6. PDF不含个人和原文。

## 5. 真实数据替换边界

模拟数据提供器与正式数据提供器都输出统一报告输入。替换时不得修改：指标计算规则、报告模板、权限规则、PDF脱敏规则和测试预期。若正式模块字段含义不同，先建立字段转换，不直接改报告逻辑。

## 6. 验收结果要求

每个场景记录：输入样本、预期结果、实际结果、差异、处理结论。统计不一致时先检查口径和数据转换，不用AI解释差异。
