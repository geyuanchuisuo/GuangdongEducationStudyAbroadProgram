## 一、给执行 Agent 的总指令

你负责粤教留学项目管理平台的 M5 智能报告模块一期交付。务必先阅读项目根目录 `AGENTS.md`、相关 M5 资料包 `00`–`06`（若 `06_后端交付说明V1.md` 存在于项目）以及本文件。以代码与有效项目规范验证现状，不得把本文未授权范围扩张为修改 M1–M4 业务逻辑。

### 工作约束

1. 先检查分支、工作树和现有实现；不得覆盖用户已有改动。
2. 遵循项目模块边界。M5 不得直接跨域查询其他模块业务表；真实数据应通过模块拥有者提供的接口/契约取得。需要上游新增字段、接口、表或迁移时，先形成清晰的 M4/M1/M3 对接任务与契约，不得擅自代替其负责人改业务逻辑。
3. AI 调用必须经公共 AI 网关；不得直连 Dify，不得复用客服/学生/员工 Agent 冒充报告专用 Agent。
4. 程序计算所有事实数字和规则；AI 只做经确认范围内的文字分析、结构化工单辅助分析，不得捏造字段、事实、时长或数值。
5. 报告快照、版本、详情、下钻、PDF 必须一致；读取旧报告不得查询实时业务数据。
6. 真实源缺失、接口失败、AI 失败必须显式表达；不得默认为 0、不得静默回退 mock。
7. 先完善测试再实现；运行与变更有关的测试、构建及静态检查，并如实记录结果。不可声称未运行的测试通过。
8. 不自行改变下列确认口径。遇到无法实现或与项目硬性规范冲突时，停止对应部分并报告阻塞和选项，不要暗自改业务含义。
9. 用户此前明确要求需求阶段不要改代码；当前文件是交给其他 Agent 执行的需求提示词。接收本提示词的 Agent 可在其执行环境按要求实施，但不得把需求访谈过程描述为已实施。

## 二、一期已确认范围与业务口径

### 2.1 报告类型与生成

- 五类报告：客户经营分析（周报/月报共用类型，以周期区分）、员工日报汇总、员工周报汇总、心理周报、投诉周报。
- 一期人工触发/手动生成；不做自动定时生成。
- 支持网页查看及 PDF 下载；不要求 Word/Excel。
- 一期完整网页闭环：类型与周期选择、手动生成、列表、历史版本、详情、下钻、PDF 下载。
- 报告生成中同类型同周期重复生成时新增版本，不覆盖旧版本。

### 2.2 周期与快照

- 使用北京时间。
- 日报按北京时间自然日；周报按北京时间自然周（周一至周日）；月报按北京时间自然月。
- 日报以填写的业务日期归属，补交仍归入原业务日期。
- 报告生成时读取并保存当时的标准化数据快照；详情、指标、摘要、下钻、PDF均基于该快照。
- 已生成报告永不因源数据变化而改变。再次明确生成同类型同周期报告时创建新版本并重新读取当时可用数据；历史版本保留。
- 旧报告查看不触发重新取数或重算。
- 报告快照保留期跟随系统统一配置；M5 不自定期限。系统未配置前不额外删除快照。

### 2.3 客户经营报告

- 周期末状态按统计周期结束时状态；不能还原的历史状态不伪造，也不为一期新增追溯/回填处理方案。
- 客户画像分类独立为四类：
  - `matched` → 符合；
  - `partial` → 部分匹配；
  - `not_matched` → 不符合；
  - `pending` → 信息不足。
- 画像按统计周期结束时最新有效研判结果；周期结束后产生的研判不用于该周期。
- 若周期末无有效研判记录，不额外归入“信息不足”，不补值；只依已有有效记录统计。
- 数据模型若尚未提供历史时点状态/画像，执行 Agent 不得以当前值冒充期末值。将受影响指标/记录标记不可得，按数据不可得处理规则展示，并把历史数据能力列为上游阻塞。
- 客户月报默认与上一个自然月比较；允许选择有数据的历史月份；选择多个月份时逐月比较。缺失/不完整月份明确提示，不当作零。同比不是强制展示，只有用户选择去年同期才形成该比较。
- 客户网页下钻展示姓名、脱敏手机号、状态、来源、负责人、最新研判及必要跟进摘要；不展示完整画像判断依据或无关客户。
- 客户 PDF 只含汇总，不含客户个人明细。

### 2.4 员工日报/周报

- 应提交人数按部门在职员工数计算；不扣除请假人员、不区分排班；尚未入职/已离职者不计入。
- 只要求周一至周五提交；周末不计应交/未交，但周末实际日报可以纳入内容汇总。
- 周报只展示本期提交率和每日提交情况，不做上周比较；不做去年同期比较。
- 日报和周报的 AI 总结仅在整体/部门层级归纳工作进展、产出、风险；不得作个人绩效评价。数字由程序计算。
- 日报与周报的提交率/提交人数计算不可用 AI 完成。

### 2.5 心理周报与个案

- 统计范围沿用 M4 现有心理统计接口的正式口径；M5 不另行定义。M4 负责人必须明确接口字段和口径；未确认不得推断。
- 学生—负责员工关系沿用 M4 现有关系/接口中的负责人字段或标识；M5 按它做授权过滤，不从客户负责人关系推导。
- 整体报告只允许 MANAGER；EMPLOYEE 只能查看自己负责的心理个案；无负责关系员工不可查看；其他角色拒绝。
- 心理网页下钻可展示完整个案详情，包括身份、联系方式、反馈原文和历史记录，且严格按以上权限校验。
- 心理 PDF 只保留总体汇总，不包含学生姓名、联系方式、具体心理反馈或个案详情。

### 2.6 投诉周报与 AI

- 一期不设置人工审核/复核流程；AI 判断，不把人工审核作为一期门槛。二期可再考虑复核机制。
- AI 在生成投诉周报时，对该周期工单批量分析。需要新增独立的工单 AI 分析表，保存工单 ID、分析分类、满意度相关信号、低满意度候选、高风险、AI 摘要、模型/来源、提示词版本、分析时间、原始输出、分析状态及错误信息等；具体 schema 遵循项目约定并最小化敏感数据。
- 每个工单若已有成功 AI 分析结果，直接复用最近一次成功结果，不因模型/提示词版本变更而重分析；没有成功结果才调用 AI。失败结果保持失败/待分析状态，不能当成功结果复用。
- AI 失败工单保留在报告快照，标“待分析”；报告仍生成。此类工单只计入工单总量，不纳入投诉分类、满意度、风险等其他 AI 分析指标；单独呈现待分析数量。后续补分析不回写已生成报告。
- 工单类型优先采用学生填写类型；缺失时由 AI 分类。必须保留类型来源标识，不能把 AI 分类伪装成学生填写。
- 只有来源为学生所选类型或 AI 分类为“投诉”的工单纳入投诉统计；建议/咨询不计入投诉指标。
- 满意度只采用学生明确提交的评价；未评价就是“未评价”，AI 不推测满意度。
- AI 可识别低满意度候选、高风险候选，并综合判断是否为特别案例；特别案例由 AI 给出归纳理由。不得展示置信度；AI 理由不得引用工单原文，须归纳表达。
- 特别案例网页与 PDF 均允许完整详情（含身份信息、工单原文和处理过程），但访问与下载仅限 MANAGER。员工和其他角色一律不可通过 API/前端绕过。
- 首次响应时间及解决时间必须由 M4 工单流程记录真实业务时间；不得 AI 推断。首次响应时长可作为已确认指标，计算 `first_response_at - created_at`。
- 超过 7×24 小时仍未解决计为超时。已解决工单一期不展示处理时长。
- 投诉 AI 分析/报告生成和快照要能追踪实际使用的分析记录及来源。

### 2.7 AI 能力

- 一期接入真实报告专用 AI，经公共 AI 网关；没有专用配置则视为交付阻塞/不可用，绝不直接复用其他业务 Agent。
- AI 只分析可用数据；部分源不可得时明确指出缺失模块，对缺失部分不推断。
- AI 输出需有 schema 校验、超时/错误处理及安全限制；失败时确定性指标仍保留，并显示 AI 分析不可用/待分析。不能把 mock 文本标成真实 AI。

### 2.8 数据源失败与数据质量

- 真实数据源某模块读取失败时，其余可用模块照常生成；不可用模块标记“数据不可得”，不填零，不回退模拟数据。
- 真正的零与缺失/读取失败必须区分。
- 报告需标明数据源状态、数据截止时间、生成时间、版本号及各模块可用性。
- 仅模拟环境可用虚构样本，并明显标为模拟；生产报告不得混入 mock。

### 2.9 权限

- 报告整体列表、详情、生成和 PDF 仅 MANAGER。
- EMPLOYEE 仅按 M4 权限关系看自己负责的心理个案；不得访问完整报告。
- 投诉特别案例完整网页/API/PDF 仅 MANAGER。
- PROSPECT、STUDENT 及其他非授权角色拒绝。
- 每个下钻/下载 API 都必须后端授权；不能依赖前端隐藏按钮。
- PDF 对客户、心理、投诉的内容分别遵循以上已确认规则，不能套用统一的“只汇总”政策覆盖用户明确允许的投诉详情。

## 三、对接契约及边界

执行前在文档中列出并与模块负责人对齐以下字段；不要假设字段已存在：

1. M1 客户：周期末状态、业务日期、客户去重主键/手机号、负责人、来源、各项目最新有效研判及其时间/状态、客户下钻允许字段、历史状态/研判可还原能力。
2. M3 员工：部门、在职起止/状态、日报业务日期、提交状态与实际提交时间、正文内容（AI 总结允许字段）。
3. M4 心理：统计接口定义、周期规则、学生—负责人关联、个案允许字段/敏感字段。
4. M4 工单：创建时间、学生选择的类型、工单状态、首次响应时间、解决时间、学生明确满意度评价、负责人/处理过程、AI 分析记录契约。
5. 公共 AI 网关：报告 Agent 配置/key 的安全配置名、调用协议、限流/超时、日志脱敏方式。密钥不写入代码、文档、报告或记忆。

若负责人或现有接口无法提供必需字段：
- 不越权修改 M1–M4；
- 产出明确字段映射/缺口表及模块 owner 待办；
- 该指标标注不可得，且不把它冒充已交付；
- 如依赖会阻塞生产闭环，最终报告注明阻塞状态。

## 四、推荐实施阶段

### 阶段 0：基线核对与契约

- 读取项目规范、现有分支与工作树，盘点 M5 现有代码/测试/路由/前端。
- 将模拟闭环、真实数据闭环、AI、页面、权限分别标明实际状态。
- 建立 M1–M4 字段映射及缺口表；与负责人确认，未确认规则不得实现为确定业务含义。

### 阶段 1：标准输入、真实数据适配与快照

- 标准化输入须兼容 mock 与 production provider，并明确来源状态。
- production provider 通过模块契约/公共接口取数，不直接查他域表。
- 报告版本持久化完整的标准化快照；必要时保存完整授权下钻快照，使旧版下钻不变。
- 数据读取按模块独立捕获失败，记录可用性，阻止 mock 静默回退。

### 阶段 2：确定性计算与报告结构

- 按确认口径计算五类报告；边界数据、去重、北京时区、日报工作日、周期边界必须有单测。
- 对不可得和真实零值采用不同结构/展示状态。
- 不在计算器中调用 AI。
- 周/月比较只在确认范围内；如果比较周期没有可靠数据，明确不可比较/不完整。

### 阶段 3：投诉 AI 分析与独立分析记录

- 新建独立 AI 分析存储及迁移（遵循 owner 边界；需 M4 负责人审批/执行的改动提供契约/任务，不私自修改 M4）。
- 优先学生类型；缺失则调报告专用 AI 分类。
- 满意度只读学生明确评价；AI 不填满意度。
- 无成功分析记录才调用；成功记录复用最近成功结果。
- 逐工单失败采用待分析，记录错误和状态；报告仍生成，待分析只计工单总量。
- 将分析结果及来源固化进本次报告快照；补分析不改变旧报告。

### 阶段 4：报告版本、权限、下钻与 PDF

- 历史版本列表/查询可用；重复生成新增版本。
- 详情、下钻和 PDF 使用版本快照。
- 完成 MANAGER/EMPLOYEE/其他角色权限矩阵 API 测试。
- 完成投诉 PDF 完整案例权限和敏感信息测试；心理 PDF 脱敏汇总；客户 PDF 无个人明细。

### 阶段 5：AI 文字分析与前端

- 报告专用真实 AI 经公共网关；只给必要、授权且脱敏的数据。
- 日报/周报只归纳整体/部门进展、产出、风险；无个人绩效评论。
- 部分源缺失时只分析有效数据并注明缺失，不猜测。
- 完成真实页面闭环，移除/显著隔离静态 mock 和静默 fallback；真实零、无数据、数据不可得、AI 不可用状态分别展示。

### 阶段 6：端到端验收和交付

- 运行相关单元、API、权限、PDF、构建测试；检查数据库迁移与回滚策略。
- 对五类报告至少用虚构固定样本人工核算；若能安全使用受控测试环境，验证真实接口，不访问未授权生产数据。
- 提交修改文件列表、迁移、字段契约、实现状态、测试输出、未完成/阻塞、风险和下一步。

## 五、必须满足的验收标准

### 数据与计算

- 五类报告均有有效生成路径；正式模式的来源为 production，不可静默使用 mock。
- 周/日/月边界采用北京时间；周一至周日完整周期，日报业务日期归属正确，补交归原业务日期。
- 部门在职员工为应交基数；周一至周五计应交，周末不计应交/未交，但实际提交内容可纳入总结。
- 画像四分类及其周期末有效结果时点正确；无记录时不补值。
- 心理口径完全对接 M4，不另行发明；负责人权限过滤有效。
- 投诉优先学生类型、缺失再 AI；仅投诉进入投诉指标；满意度只统计学生明确评价；待分析只入工单总量；时效事实字段系统记录；7×24h 未解决计超时；已解决时长不展示。
- 对数据不可得、缺失、真实零值有差异化结果和 UI。

### 快照与版本

- 报告快照包含本次生成使用的标准化数据及源状态/时间。
- 旧报告指标、文本、下钻、PDF在源数据变化/AI 补分析后不变。
- 同类型同周期再次生成新增版本，旧版本保留。
- 每个版本的详情、下钻、PDF完全一致。

### 安全与展示

- 非 MANAGER 不能访问完整报告、生成、PDF、投诉特别案例。
- EMPLOYEE 心理个案仅本人负责关系可访问；跨员工 ID、跨报告 ID 越权测试拒绝。
- 客户 PDF 无姓名/电话等个人下钻；心理 PDF 无身份/联系方式/反馈；投诉特别案例只给 MANAGER，按确认允许完整网页/PDF。
- 日志不得泄漏工单原文、心理反馈、密钥或完整个人敏感数据。

### AI

- 使用公共网关及报告专用配置；没有配置不得声称真实 AI 已接入。
- AI 不计算数字、不推断满意度、不从文本编造时长；不引用投诉原文作为 AI 判断理由。
- schema 校验、失败降级、待分析与来源标识通过测试。

## 六、不得擅自扩展或改变的事项

- 一期不增加人工审核；人工审核仅二期考虑。
- 不增加自动调度、Word/Excel、NL2SQL、心理测评、复杂同比环比、高价值客户规则。
- 不自行定义画像/心理/投诉字段业务含义。
- 不用当前客户状态冒充过去周期末状态。
- 不因缺历史数据而自行选默认分类/零值。
