# 粤教留学前端第一版设计方案

## 1. 设计目标

第一版交付一套可点击、可演示、可逐步接入后端的完整前端界面，覆盖公开主页、意向客户中心、学生端、员工端和管理端。

核心目标： 

- 访客无需登录即可了解公司、项目、课程与近期活动。
- 项目报名和活动报名必须登录，登录后自动返回原页面并恢复报名状态。
- 登录后按用户身份进入学生端、员工端、管理端或意向客户中心。
- 后端已经提供的接口使用真实请求；暂未提供的接口通过统一模拟数据层演示。
- 页面内容严格遵循现有需求、业务模块、智能汇总口径和用户画像研判提示词，不添加未经确认的指标或功能。
- 所有员工写操作、删除操作和 Agent 指令式业务操作均提供二次确认。

## 2. 范围与角色

### 2.1 未登录访客

可以浏览：

- 公司介绍
- 四大业务项目
- 课程与项目
- 近期活动
- 留学政策
- 常见问题

所有报名入口均要求登录。未登录点击报名时显示登录弹窗；登录成功后自动返回原项目或活动，并恢复报名状态。

### 2.2 意向客户 PROSPECT

进入精简的意向客户中心：

- 浏览课程与活动
- 提交咨询
- 管理自己的项目和活动报名
- 查看账号审核状态
- 查看消息通知

注册成功后账号状态为“待开通”，由员工审核开通完整服务权限。

### 2.3 留学生 STUDENT

进入学生端：

- 行政服务
- 心理关怀
- 售后反馈
- 学业考务
- 进度追踪
- 生活支持
- 更多服务
- 个人信息

### 2.4 员工 EMPLOYEE

进入员工端：

- 客户经营
- 学生业务综管
- 日报
- 组织与指引
- 待办与消息
- 个人信息

### 2.5 管理层 MANAGER

一期不区分经理和总裁，统一使用 MANAGER 权限。进入管理端：

- 智能汇总
- 客户经营
- 审批中心
- 员工管理
- 权限配置
- 消息与日志
- 个人信息

第一版不设计独立系统管理员业务界面。测试管理员只作为后台种子账号存在。

## 3. 公开主页信息架构

一级导航：

1. 首页
2. 公司介绍
3. 业务项目
4. 课程与活动
5. 留学政策
6. 常见问题
7. 登录 / 注册

页面顺序：

1. 品牌与四大业务线首屏
2. 公司介绍
3. 项目与课程推荐
4. 近期活动
5. 留学政策摘要
6. FAQ
7. 联系与咨询

右下角常驻“小粤”智能客服。

### 3.1 首页

- 公司品牌、成立年份和国际化教育定位
- 四大业务线：中德双元制、新加坡国际本硕、国际留学、国际研学
- 免费评估、预约咨询、查看项目等主要入口
- 热门项目和近期活动
- 公司资质、服务优势和联系信息

### 3.2 公司介绍

公开内容：

- 公司简介与发展沿革
- 使命与价值观
- 主营业务
- 四大核心业务线
- 部门架构
- 服务优势
- 办公地址和官方联系方式

不公开新人指南中的内部办公流程、内部系统和员工私人联系方式。

### 3.3 项目详情

项目详情字段：

- 项目名称和业务线
- 适用人群
- 培养路径
- 学制
- 费用范围
- 项目优势
- 报名条件
- 办理流程
- 报名咨询按钮

费用范围公开；缴费账号、合同金额和个性化报价仅在登录后或由顾问确认后展示。

### 3.4 活动详情

活动字段：

- 活动名称
- 日期与时间
- 线上或线下形式
- 地点或直播入口
- 主讲人
- 活动说明
- 名额与报名状态
- 报名须知
- 报名按钮

活动状态包括：报名中、名额紧张、已满员、已结束、已取消。已满员、已结束和已取消活动禁止报名。

### 3.5 留学政策

- 按德国、新加坡和综合主题分类
- 展示政策摘要、更新日期、费用和申请要点
- 提供完整指南入口

### 3.6 常见问题

FAQ 分类：

- 公司信息
- 项目业务
- 报名流程
- 费用政策
- 申请材料
- 签证与入学
- 学生服务

支持搜索、分类筛选和折叠展开。

## 4. 注册、登录与报名

### 4.1 注册

手机号作为登录账号和客户唯一标识。界面采用“手机号 + 短信验证码”流程，第一版使用模拟验证码，后续替换真实短信服务。

注册字段：

必填：

- 姓名
- 性别
- 年龄
- 手机号
- 最高学历

选填：

- 职业或专业需求
- 德语能力

“家庭经济状况”不在注册表单展示。员工 CRM、客户研判和 Agent 对话中获得的经济信息仍可作为辅助研判信息。

提交后账号显示为“待开通”。

### 4.2 登录

登录使用手机号、密码和短信验证码。第一版不增加找回密码流程，无法登录时引导联系负责员工或管理员。

登录后路由：

- STUDENT：学生端
- EMPLOYEE：员工端
- MANAGER：管理端
- PROSPECT：意向客户中心

### 4.3 报名

项目报名和活动报名必须登录：

- 已登录用户可直接报名。
- 未登录用户点击报名后弹出登录窗口。
- 登录成功后自动返回原详情页。
- 恢复此前选择、表单草稿和当前报名步骤。

报名时自动带入账号资料，并允许修改。修改结果保存为本次报名快照；用户可以选择是否同步更新账号主资料。

## 5. 学生端

### 5.1 学生首页

首屏内容：

- 欢迎与身份信息
- 近期课程和截止事项
- 我的待办
- 留学申请进度
- 心理状态概览
- 七个服务入口

右下角常驻“粤伴”学生智能助手。

### 5.2 行政服务

- 请假类型：事假、病假、考试假、其他
- 开始时间、结束时间
- 预计缺课
- 请假事由
- 紧急联系人
- 可选附件
- 审批状态和历史记录

同一学生同一时间段已有“审批中”或“已通过”的请假申请时，阻止重复提交并提示。

审批为单层审批：学生提交，负责员工审批。

### 5.3 心理关怀

- 0 至 100 的服务性综合状态评分
- 情绪标签
- 触发因素
- 情绪历史与趋势
- 对话式评估
- 高风险识别结果
- 服务边界
- 专业心理咨询渠道

评分明确标注“不构成医疗诊断”。

高风险通知链：

1. 更新学生心理记录。
2. 根据后台可配置风险规则识别高风险。
3. 自动生成心理预警并关联负责员工。
4. 发送站内消息。
5. 在员工工作台生成心理关怀待办。
6. 企业智能助手主动提醒负责员工。
7. 员工记录已沟通、已转介或已解决状态。

不等待周报才通知，不在学生端暴露内部预警处理细节。

### 5.4 售后反馈

工单状态：

1. 待处理
2. 处理中
3. 已反馈
4. 已解决

反馈分类：

- 服务咨询
- 课程安排
- 费用问题
- 住宿生活
- 投诉建议

只有明确选择并确认“正式投诉”的工单进入投诉周报统计。普通咨询和建议不计入投诉量。

### 5.5 学业考务

- 作业与考试安排
- DDL
- 成绩
- 智能提醒设置
- 提醒记录

### 5.6 进度追踪

固定六阶段：

1. 材料审核
2. 申请提交
3. 收到 Offer
4. 签证办理
5. 行前准备
6. 已入学

每阶段展示备注、更新时间和负责员工。

### 5.7 生活支持

- 住宿、交通、医疗、法律与安全指南
- 常见生活问题
- 紧急联系人
- 一键求助

### 5.8 更多服务

面向学生的温和推荐模块，不使用“增值转化”等内部术语：

- 学业规划
- 课程升级
- 背景提升
- 语言进阶
- 职业发展
- 定制服务

明确说明推荐服务为可选项，不影响原有服务权益。

### 5.9 个人信息

- 基本资料
- 密码修改
- 我的成绩
- 申请进度
- 请假记录

## 6. 员工端

### 6.1 员工首页

首屏内容：

- 今日待办
- 客户跟进提醒
- 待审批事项
- 名下客户概览
- 本月转化数据

右下角常驻“粤助”企业智能助手。

### 6.2 客户经营

- 客户录入
- 客户列表
- 客户详情
- 客户研判结果
- 跟进记录
- 客户状态更新

客户录入支持：

- 文字
- PDF
- 照片
- Word
- Excel
- Agent 对话

上传限制：

- 单文件不超过 20MB
- PDF、Word 不超过 100 页
- Excel 不超过 5000 行
- 图片支持 JPG 和 PNG

客户状态使用六态：

1. 新录入
2. 跟进中
3. 意向强烈
4. 已签约
5. 已入学
6. 已流失

状态切换必须符合既定流转顺序，不允许非法跳转。

客户研判严格按照《研判提示词》展示：

- 有效性状态
- 四级结论：符合、部分符合、待确认、不符合
- 新加坡项目与中德项目分别研判
- 推荐项目及理由
- 逐维度证据
- 缺失信息
- 客户速览
- 跟进建议

不展示未经业务定义权重的百分制匹配度。

### 6.3 手机号去重与归属

- 同一手机号仅保留一个客户档案。
- 后续信息自动合并。
- 员工首次录入时，首个录入员工获得跟进权。
- 访客先注册、员工后补充录入时，首个完成有效补充的员工获得跟进权。
- 无归属客户进入待分配。
- 管理层可调整客户归属。

客户有效性：

- 手机号通过验证即为有效线索。
- 信息缺失时标记“信息待补充”。
- 明显矛盾信息标记“待核实”。
- 无手机号的咨询只记录咨询日志，不进入 CRM。

### 6.4 学生业务综管

- 代客申请留学生
- 学生流程审批
- 成绩录入
- 学生申请进度维护

意向客户转留学生采用一次审批：

员工申请，管理层一次审批通过。驳回后允许修改原申请并重新提交。完整保留审批记录。不支持中途加签、转交或自动升级。

### 6.5 日报

- 文字日报
- 口述日报
- AI 结构化预览
- 保存草稿
- 日报历史

当日日报可保存并在次日 0 点前补提。次日 0 点后需发起日报补报申请，由管理层一次审批后入日报记录。

### 6.6 组织与指引

- 组织架构查询
- 部门职能
- 同事联系方式
- 新人引导任务
- 知识库

列表中的手机号默认脱敏。组织架构联系方式二次确认后展开。

### 6.7 待办与消息

- 客户跟进
- 审批
- 反馈处理
- 心理关怀
- 系统提醒

### 6.8 员工写操作

以下操作必须二次确认：

- 新增客户或研判信息
- 修改客户核心资料
- 更新客户状态
- 添加或删除跟进记录
- 提交或删除日报
- 提交代客申请
- 录入或修改成绩
- 审批通过或驳回

删除操作使用更强的风险提示，并明确说明影响范围。

## 7. 管理端

### 7.1 管理首页

首页不堆叠模块外的经营指标。主内容为：

- 智能汇总五类报告入口和状态
- 审批中心待办
- 现有模块常用入口
- 消息提醒

数据指标仅出现在对应报告详情中。

### 7.2 智能汇总

五类报告：

1. 客户经营分析报告：周报、月报
2. 员工日报汇总：日报、周报
3. 学生信息健康周报
4. 投诉处理周报
5. 自定义分析报告

图表配置：

- 客户经营分析：新增意向趋势、转化路径、流失与回流趋势、新加坡和德国项目对比、研判结果占比、同比与环比。
- 员工日报汇总：部门提交情况、团队进展变化、风险事项数量和周对比。
- 学生信息健康周报：整体情绪趋势、风险人数变化、考试和假期节点。
- 投诉处理周报：投诉量趋势、处理率、平均首次响应时间、超过七天未解决数量、满意度评价状态。
- 自定义分析：根据开放维度生成柱状图、趋势图或对比图。

所有图表支持明细下钻，但个体数据继续遵守权限与脱敏规则。

报告口径：

- 客户经营报告按周、月展示，并按新加坡和德国项目分别统计。
- 员工日报只按部门展示团队进展和风险，不展示或评价个人明细。
- 学生心理周报展示整体态势、风险人数和周变化，个体信息按职责权限访问。
- 投诉周报只统计正式投诉，不包含咨询和建议，不做投诉分类。
- 特别投诉案例须经投诉负责人复核后展示。
- 处理时效从投诉提交到首次响应计算。
- 超过七天未解决标记为长期未解决。
- 无满意度反馈标记为未评价。

### 7.3 客户经营

- 全部客户查询
- 客户详情
- 研判结果
- 跟进记录
- 客户归属调整

### 7.4 审批中心

- 待处理
- 已处理
- 审批详情
- 通过或驳回
- 通知状态

### 7.5 员工管理

- 员工账号
- 部门
- 角色
- 状态
- 权限入口

### 7.6 权限配置

- 管理层权限项配置
- 权限变更记录

### 7.7 消息与日志

- 审批结果
- 预警通知
- 系统公告
- 关键操作日志

## 8. 智能助手

第一版包含三个常驻助手：

- 公开端：小粤
- 员工端：粤助
- 学生端：粤伴

窗口结构：

- 快捷问题
- 对话历史
- 信息提取卡片
- 操作确认卡片
- 服务边界提示
- 输入框和附件入口

第一版使用模拟对话，但交互结构按后续接入 Dify 的方式设计。

员工端 Agent 的写操作必须展示二次确认卡片。越权请求明确拒绝并说明原因。学生端心理服务不得提供医疗诊断，不得承诺退费或转学等重大决定。

## 9. 视觉设计

### 9.1 整体方向

采用参考图 1 的配色和布局气质：

- 深靛紫作为品牌主色
- 亮紫用于选中、链接和强调
- 黄绿色用于重点和积极状态
- 暖黄用于提醒
- 浅绿色用于温和信息
- 白色卡片
- 浅灰紫页面背景

### 9.2 字体

- 中文使用现代无衬线字体
- 英文和数字使用 Inter 类无衬线字体
- 标题加粗
- 正文清晰
- 不使用书法体、复杂衬线体或装饰字体

### 9.3 卡片与布局

- 白色圆角卡片
- 轻阴影
- 浅灰紫内容背景
- 白色侧边栏
- 深靛紫顶部欢迎区
- 卡片标题使用小色块标记
- 重要数据使用大号数字
- 图标使用统一线性图标
- 不使用 Emoji 作为正式界面图标

### 9.4 公开页面素材

公开主页以真实留学、校园、国际交流和研学照片为主，搭配简洁几何线条和大标题。登录后的业务页面以数据卡片和图表为主，不堆叠照片。

### 9.5 入场动画

总时长约 2 秒：

1. 0 至 0.4 秒：深靛紫品牌画面进入。
2. 0.4 至 1.0 秒：品牌标识与几何线条出现。
3. 1.0 至 1.6 秒：公司名称和品牌短语完成组合。
4. 1.6 至 2.0 秒：画面展开并过渡到公开主页。

动画必须支持 prefers-reduced-motion；系统开启减少动画时直接进入主页。

## 10. 状态与反馈

统一状态：

- 加载中
- 空数据
- 保存成功
- 提交成功
- 删除确认
- 驳回确认
- 无权限
- 接口未开放
- 网络错误
- 会话过期

模拟数据页面使用“演示数据”标签。页面顶部保留“演示原型”标识。接口未开放时仍提供完整可点击的模拟流程，不将空白误认为系统故障。

## 11. 后端接入策略

### 11.1 当前可真实接入

- 登录
- JWT 保存和请求鉴权
- 获取当前用户
