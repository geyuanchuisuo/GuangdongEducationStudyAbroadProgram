# 智能报告模块项目执行方案

需求梳理与跨部门协调工作方案

本方案说明我如何围绕智能报告模块开展需求梳理与跨部门协调，并将五类报告的业务目的、使用对象、指标口径、数据依赖、权限要求、验收方式和待办事项整理成统一需求文档。报告内容以客户需求表为基础；已由你确认的信息作为明确要求，尚未形成的规则统一标为待确认，供对应部门负责人确认。

| 我的职责范围｜组织访谈和梳理、推动对应部门负责人确认、记录决策与未决事项、汇总形成需求文档。报告指标、数据口径和流程由业务部门确认；具体实现、个案处置及业务动作由相应责任团队负责。 |
| --- |

## 一 项目目标与职责边界

### 1.1 项目目标

智能报告模块面向客户经营、员工管理、学生关怀和投诉服务等工作，将已有业务记录整理为周期性报告，帮助管理者掌握趋势、发现风险、确定需要跟进的事项。报告中的事实、统计、分析和建议应能区分；涉及个人或高风险情形时，应按职责限制查看范围并由责任人复核。

### 1.2 我的工作方式

- 与各报告相关部门访谈，收集业务目标、使用场景、指标需求、样例和现行处理方式。
- 组织部门负责人逐项确认报告定义、指标口径、数据来源、分类和预警规则、可见范围及验收标准。
- 记录已确认事项、建议方案、待确认问题、负责人和后续状态；协调跨模块依赖与部门间分歧。
- 将确认结果汇总成一份统一需求文档，供后续设计、实现和验收团队使用。
- 不替代部门负责人作业务判断，不直接执行学生关怀、投诉处理、员工管理或客户经营动作。

## 三 需求梳理与协调步骤

1. 启动范围确认：逐条核对五类报告、报告周期、受众、提供方式和查看权限；确认各报告对应部门负责人（目前待指定）。建立需求、决策、风险和待办记录。
1. 开展部门访谈：分别与客户经营、员工管理、学生服务和投诉服务相关人员沟通，了解报告要支持的决策、日常流程、现有指标和未解决问题。使用实际业务场景询问“看到这个结果后谁要做什么”。
1. 共同梳理指标与口径：下一轮与部门负责人一并梳理五类报告的指标、定义、统计周期、去重、状态归属、同比 / 环比、分类规则、特殊样本和例外情形。对未确认内容保留问题，不自行补定。
1. 盘点数据来源与依赖：与各部门逐项确认报告需要哪些业务记录、所在模块、数据责任部门、字段解释、更新情况、缺失情况及可查看范围。覆盖客户研判、客服Agent、企业智能助手和学生智能助手。
1. 整理报告结构和样稿需求：依据目标读者设计摘要、趋势、分群 / 部门、重点风险、依据和跟进行动等内容结构；待项目实际开展时由业务部门提供案例，用于完善模板和验收样例。
1. 梳理隐私和处理规则：与对应负责人确认个体信息展示范围、查看权限、人工复核、紧急通知、纠错及留存等业务要求；特别核对心理健康信息和员工日报的可见边界。
1. 组织需求确认：将报告定义、指标字典、数据依赖、模板结构、权限、验收示例和未决事项提交给对应部门负责人确认；记录修改意见、确认结论和责任人。
1. 协调后续闭环：将报告发现的问题和建议整理为跟进事项，列出负责部门 / 负责人、处理状态和反馈；我负责记录、协调和汇总，不承担事项执行。
## 四 五类报告的业务设计建议

### 4.1 全域客户经营分析报告

| 已确认：面向总经理和总裁；按周、按月周期性提供并支持自行查看；可查看具体客户或案例；周报和月报均展示同比、环比。 |
| --- |

#### 已确认的客户定义与统计规则

- 意向客户：所有在网站注册并登录过的用户，以及员工提交过信息的客户。
- 客户去重：手机号为唯一标识；网站注册与员工提交重复时合并为同一客户。
- 新增意向客户：按首次网站注册登录或首次员工提交信息的时间计入统计周期。
- 成交客户：员工在系统中更新为成交状态时计入；成交转化路径按系统中的客户状态展示。
- 流失客户：首次注册登录后 90 天内没有再次登录，且历史上从未有员工提交过该客户信息。
- 流失客户重新登录或后来有员工提交信息后，移出流失状态并重新计入意向客户。
- 一期不展示或归纳流失原因；高价值客户标准放到二期确定。

#### 画像分析规则

- 按《用户画像研判规则.docx》中的新加坡国际本硕升学计划和中德精英人才共建计划分别统计；同一客户若同时符合两个项目画像，在两个项目中分别计入。
- 直接采用客户研判模块的最终结果，不在报告中重新判断。每个项目分别呈现“符合画像”“不符合画像”“信息不足、待补充”的数量、占比和变化趋势。
- 占比分母为该项目该统计周期内的全部意向客户；报告保持简洁，不展示个人具体画像依据。

### 4.2 员工日报汇总报告（日 / 周）

| 已确认：面向公司管理层；按部门汇总，周期性提供并支持自行查看；仅显示团队整体进展和风险，不展示员工个人明细。 |
| --- |

- 日报、周报均按部门组织，展示团队整体进展、关键产出和风险；具体指标定义由各部门负责人确认。
- 显示各部门应提交、已提交和未提交日报人数。
- 周报需要对比上一周的团队进展与风险变化。
- 汇总只用于团队层面掌握工作进度和风险，不据此评价个人员工。

### 4.3 学生心理健康周报

| 已确认：每周生成。公司管理层可查看整体趋势和个案身份信息及具体反馈；学生顾问、老师仅按职责查看相关个案；周报不提供给管理层以下的其他人员。 |
| --- |

- 汇总情绪打卡、学业压力和跨文化适应情况；对比上一周的变化，并结合考试、假期等特殊节点解读。
- 汇总页重点呈现整体心理态势、风险人数和相较上周的变化，不需要加入通知确认、个案跟进状态和处理结果等细节。
- 高风险个案采用学生智能助手已有的风险识别结果；识别后自动通知该学生对应负责人，不等待周报生成。
- 个案信息按已确认的权限查看。高风险响应时限和后续处理流程仍待确认；建议讨论“识别—自动通知负责人—核实—联系学生并安排支持—记录处理”的流程。
- 一期不要求部门负责人审核整份心理周报；高风险个案的接收与处置由学生对应负责人跟进。

### 4.4 投诉处理周报

| 已确认：每周生成，周期性提供给公司管理层并支持自行查看；以汇总趋势为主，可查看特别案例。 |
| --- |

- 只统计正式投诉，不包括一般建议和咨询；投诉不做类别分类。
- 特别案例包括低评分或高风险投诉。低评分 / 高风险由 AI 识别后交投诉负责人人工复核，复核后才展示给管理层。
- 管理层查看特别案例时，只需显示负责人和处理进度。
- 长期未解决定义为受理后超过 7 天仍未解决；处理时效按投诉提交到首次响应计算。
- 无满意度反馈标记为“未评价”，不计入满意或不满意。
- 一期由 AI 智能评估；二期考虑纳入测量表。客户需求表中其他未确认指标和口径由投诉部门负责人确认。
- 一期不要求部门负责人审核整份投诉周报，但特别案例按上述规则由投诉负责人复核。

## 六 统一报告规则与权限要求

### 6.1 报告应清楚呈现的信息

- 报告名称、统计周期、更新时点、覆盖范围及使用部门。
- 每项指标的名称、定义、统计范围、状态口径、去重方式、比较周期和数据责任人。
- 事实数据、趋势分析、AI归纳和建议动作应清晰区分；推断需标注为待核实。
- 数据缺失、延迟、样本不足或分类不确定时，说明对结论的影响。
- 行动事项列明负责部门 / 负责人、处理状态和后续反馈；责任人由对应部门指定。
### 6.2 权限与复核要求

| 报告 / 内容 | 查看范围 | 复核要求 |
| --- | --- | --- |
| 客户经营报告 | 总经理、总裁；允许查看具体客户或案例。 | 指标口径由相关部门负责人确认；重要归因和建议应能追溯依据。 |
| 员工日报 / 周报 | 公司管理层；按部门看团队整体进展与风险，不看个人明细。 | 部门汇总须忠实于团队记录；不据此评价单个员工。 |
| 学生心理周报 | 公司管理层可看趋势和个案详情；学生顾问、老师按职责看相关个案；其他管理层以下人员不接收周报。 | 高风险即时通知学生对应负责人；个案复核和跟进由责任人完成；响应时限待确认。 |
| 投诉周报 | 公司管理层；先看汇总，可查看特别案例。 | 一期AI评估结果需投诉负责人复核后展示；正式阈值和口径待确认。 |

## 七 验收要求与示例

验收标准由对应部门负责人结合指标口径确认。以下示例用于说明验收时应检查什么，不预设尚未确认的数值阈值。

| 报告 | 示例验收场景 | 验收关注点 |
| --- | --- | --- |
| 客户经营 | 客户记录有重复、缺失和状态变更；比较周期样本不足。 | 按确认的去重和状态规则统计；缺失与不可比情况明确标出；个案下钻内容符合管理权限。 |
| 员工日报 / 周报 | 同一事项跨日更新、存在部门归属和未提交记录。 | 按部门汇总进展与风险；周报反映持续事项；不展示个人明细、不推断个人绩效。 |
| 学生心理周报 | 参与人数变化、考试周压力上升，出现一条高风险提示。 | 呈现样本和阶段背景；不把提示作为诊断；紧急情况即时通知学生对应负责人；非授权人员看不到周报或个案。 |
| 投诉周报 | AI发现低评分 / 高风险候选投诉；负责人复核前后展示内容不同。 | 复核前不向管理层展示为正式特别案例；复核后可查看汇总和授权范围内个案；未确认口径不伪装成正式标准。 |

### 7.1 通用验收条件

- 关键数据与人工核对样本一致，差异可解释并能定位到来源或口径。
- 报告覆盖明确的周期和对象，结论与源记录相符，不夸大确定性。
- 目标读者能找到主要趋势、风险、依据和跟进事项。
- 个人信息只对明确授权角色展示；人工复核、纠错和紧急通知要求清晰。
- 报告发现的问题能落实到部门 / 负责人和处理状态，后续可追踪。
## 八 已逐项确认的业务口径

本节汇总本轮逐项确认结果，后续需求文档和部门会议记录以此为准；已确认事项不再重复询问。

### 8.1 客户经营分析

| 主题 | 已确认口径 |
| --- | --- |
| 意向客户 | 网站注册并登录过，或员工提交过信息。 |
| 去重 | 手机号为唯一标识；重复渠道合并。 |
| 新增意向 | 按首次注册登录或首次员工提交的时间计入。 |
| 成交 | 以员工在系统中更新的成交状态为准；转化路径使用系统状态。 |
| 流失 | 首次注册登录后 90 天无再次登录，且历史上没有员工提交记录。 |
| 流失客户回流 | 再次登录或后来有员工提交信息后，移出流失并重新计入意向客户。 |
| 项目画像 | 新加坡项目、中德项目分开统计；同时符合两项的客户在两项中都计入。 |
| 画像结果 | 采用客户研判模块最终结果，按符合、不符合、信息不足三类统计数量、占比和趋势；占比分母为该项目该周期全部意向客户。 |
| 报告呈现 | 周报、月报均需要；均展示同比、环比；保持简洁，可查看客户或案例。 |
| 一期 / 二期边界 | 一期不分析流失原因；高价值客户标准二期确定。 |

### 8.2 员工日报汇总

日报和周报面向公司管理层，按部门汇总，周期性提供并支持自行查看；只展示团队整体进展和风险，不展示个人明细。各部门应提交、已提交、未提交人数需纳入；周报对比上一周团队进展和风险。

### 8.3 学生心理健康周报

周报汇总页展示整体心理态势、风险人数及周变化，结合考试、假期等特殊节点；高风险结果使用学生智能助手的识别结果并自动通知学生对应负责人。管理层可查看趋势及个案身份信息、具体反馈；学生顾问和老师按职责查看相关个案，其他管理层以下人员不接收整份周报。响应时限与后续流程待确认。一期不审核整份报告。

### 8.4 投诉处理周报

只统计正式投诉，不分类；每周提供给管理层并支持自行查看。AI识别低评分 / 高风险候选，投诉负责人复核后再展示；管理层看特别案例只需负责人和处理进度。处理时效为提交至首次响应；超过 7 天未解决为长期未解决；无满意度反馈记为未评价。一期由AI评估，二期考虑测量表；一期不审核整份报告。

### 8.5 跨报告职责

五类报告所需数据都保存在后端数据库。报告发现的问题或建议需列跟进动作、负责部门 / 负责人和处理状态；你负责记录、协调、汇总，不负责执行。报告样例由相关部门在项目实际开展时提供。

## 十 协调闭环

1. 每次访谈后记录确认结论、未决问题、确认人和后续动作；不把待确认项写成已生效规则。
2. 对跨模块数据依赖，记录来源模块、字段、业务责任部门、更新情况、权限和缺失影响。
3. 对报告中的建议事项，记录负责部门 / 负责人、处理状态及反馈；你负责跟进协调和汇总，不承担具体业务执行。
4. 项目实际开展后，由对应部门提供样例并参与核对；根据反馈更新需求文档和验收要求。
