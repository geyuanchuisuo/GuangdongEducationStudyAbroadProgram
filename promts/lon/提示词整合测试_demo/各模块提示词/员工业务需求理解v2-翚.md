### 企业智能助手Agent（员工/管理层端）
1. 部署位置：员工端右下角置顶，所有页面可见
2. 核心策略：
	1. 主动提醒：提醒员工未达成任务、待跟进客户、待审批事项
	2. 权限感知：根据当前用户角色和权限，开放不同的查询和操作能力
	3. 数据隔离：普通员工只能查询自己名下的客户；管理层可查询全域
	4. 指令执行：支持指令式业务处理（如"帮我给张三添加跟进记录"），执行前需二次确认
	5. 日报整理：员工口述工作内容，AI自动整理成结构化日报格式
3. 功能：CRM管理、日报整理、待办提醒、指令式处理
4. 工作流：
```
员工输入 → 意图识别 → 权限校验 → 功能路由
    ├─ 客户查询 → 校验数据隔离 → 返回名下客户列表
    ├─ 录入客户 → 提取信息（文字/文件） → 有效性判断 → 录入CRM
    ├─ 添加跟进 → 提取信息 → 调用API添加记录 → 返回确认
    ├─ 口述日报 → 语音转文字 → AI整理成结构化格式 → 确认 → 提交
    ├─ 待办查询 → 查询待办列表 → 返回
    ├─ 指令处理 → 解析指令 → 执行操作 → 二次确认 → 提交
    └─ 新人指引 → RAG检索新人手册 → 引导式回答
```

- 管理层额外能力：
```
    ├─ 全域客户查询 → 返回所有客户数据
    ├─ 经营状况 → 查询经营数据 → 生成分析
    ├─ 流程审批 → 查询待审批列表 → 执行审批
    └─ 日报汇总 → 汇总员工日报 → 生成报告
```
- Agent补充：
	1. 意图识别边界
		1. 明确Agent无法处理的场景（如：涉及薪资、人事任免等非授权指令），需返回"权限不足"或"请联系HR"
	2. 二次确认的交互形式
		1. 定义确认UI：弹出卡片显示"即将执行：给客户张三添加跟进记录「已发送方案，等待回复」，确认？`[确认][取消]`"
	3. 多轮对话上下文
		1. Agent是否支持多轮
			1. 如："查一下李四"→"给他加个跟进"→"今天电话沟通了，约了周五面谈"。一期支持5轮以内上下文
	4. 文件解析格式
		1. 明确支持的文件大小限制、页数限制（常用大小）
	5. 语音输入
		1. 依赖的ASR服务，以及离线降级方案（手动输入）
	6. 主动提醒的触发时机
		1. 登录时拉取+关键动作后实时推送（如新投诉工单创建）

## 模块内容补充
### 口述日报结构化格式：
```
日期：2026-10-15
姓名：张三（员工）
部门：新加坡事业部

一、今日工作
1. 跟进意向客户2名（李四-新加坡项目咨询、王五-德国项目报名）
2. 完成3份项目方案
3. 参加部门会议

二、明日计划
1. 继续跟进客户李四
2. 准备培训材料

三、问题与反馈
- 客户王五对费用有疑虑，需要进一步沟通
```

### 业务流程

```
1. 意向客户访问公开主页
2. 与智能客服Agent对话（Agent主动采集信息）
3. 意向客户自行注册（填写必填+选填信息）
   → 账号状态为"待开通"
4. 员工审核并开通功能权限
5. 员工将意向客户转化为留学生（需经理审批）
   → user_type: PROSPECT → STUDENT
6. 留学生使用平台服务
7. 负责的员工审批留学生提交的流程
```


### 行政服务（请假）
```
流程：
1. 留学生在页面提交或通过Agent对话提交请假申请
2. 校验：同一学生同一时间段已有请假记录时，提示"已有请假申请审批中/已通过"
3. 系统创建审批流程，写入数据库
4. 负责该学生的员工收到审批通知
5. 员工审批（通过/驳回），写入数据库
6. 审批结果通过站内消息+Agent推送给学生
```

### 心理关怀（情绪疏导+预警）
```
流程：
1. 学生与Agent对话，Agent进行情绪疏导
2. AI在对话中分析情绪状态（一期：对话式评估，不做标准化量表）
3. 输出情绪标签+评分，写入心理画像表
4. 若情绪评分低于阈值，触发预警（通知负责员工）
5. 二期引入专业心理测评量表
```

### 售后反馈
```
流程：
1. 学生在页面提交或通过Agent对话提交反馈工单
2. 系统创建工单，状态为"待处理"
3. 负责员工查看并处理
4. 处理结果反馈给学生
```

### 进度追踪
```
功能：
- 留学申请各阶段进度查看
  - 材料审核 → 申请提交 → 收到Offer → 签证办理 → 行前准备 → 已入学
- 每个阶段的备注和更新时间
- 由负责员工在后台更新进度
```
