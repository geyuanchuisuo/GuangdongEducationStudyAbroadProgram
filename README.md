---

## 一、项目背景

**广东省教育服务有限公司**（简称「粤教服务」）创办于 1981 年，2024 年 3 月划转至广东教育国际交流服务中心有限公司（「粤教国际」）。公司主营业务覆盖国际教育、智慧教育、素质教育和实体教育。

核心业务线：

| 业务 | 说明 |
|------|------|
| **德国双元制职业教育** | 中德精英人才共建计划 |
| **新加坡国际本硕升学** | 定向培养联合办学项目 |
| **国际留学** | 全球数百所院校合作 |
| **国际研学** | 面向中小学生、高职高专及大学生 |

**项目目标**：构建一个覆盖 **意向客户获取 → 客户研判 → 留学申请 → 学生服务** 完整业务闭环的智能化平台，集成三大 AI 智能体能力 + 五类业务智能报告。

## 四、业务流程

### 4.1 客户生命周期

```
访客访问公开主页
    │
    ▼
与智能客服 Agent 对话（7 大场景 + 主动采集信息）
    │
    ├─→ 浏览课程/活动/政策资讯（无需登录）
    │
    ▼
自行注册（手机号为唯一有效性标准）
    │
    ▼
员工录入客户信息（多渠道：文字 / PDF / 照片 / Word / Excel / Agent 对话）
    │
    ▼
客户画像研判（AI 提取 + 本地规则兜底 → 8 个研判字段）
    │
    ▼
状态 6 态流转：新录入 → 跟进中 → 意向强烈 → 已签约 → 已入学
    │
    ▼
员工代客申请留学生（需经理审批）
    │
    ▼
approval.approved 事件触发
    │
    ▼
身份自动转换：user_type PROSPECT → STUDENT + customer.status → ENROLLED
    │
    ▼
留学生使用平台服务（请假 / 心理关怀 / 售后反馈 / 学业考务 / 进度追踪）
    │
    ▼
员工审批学生流程 → 结果通过站内消息 + Agent 推送给学生
```

### 4.2 审批流程

```
┌──────────┐     提交       ┌──────────────┐    审批     ┌──────────────┐
│  学生     │ ─────────────→ │  负责员工     │ ─────────→ │  经理/总裁    │
│  请假     │               │ （自动解析）  │            │              │
│  工单     │               │              │            │              │
└──────────┘               └──────────────┘            └──────┬───────┘
                                                             │
                                              ┌──────────────┼──────────────┐
                                              ▼ 批准        ▼ 驳回        ▼ 变更归属
                                         publish       通知学生        事件通知
                                         approval.     用户更新        新 owner
                                         approved
                                              │
                                              ▼
                                         自动执行
                                        （身份转换/
                                        状态流转等）
```

### 4.3 数据流向

```
前端请求 → FastAPI 路由 → Service 业务层 → Repository 数据访问层 → MySQL 35 张表
                  │
                  ├─→ AIService.chat() → Dify Agent → 知识库 RAG 检索 → 回复
                  │
                  ├─→ EventBus.publish() → 事件消费方（审批/通知/状态流转）
                  │
                  └─→ 通知中心 → sys_notification → Agent 主动推送 / 站内消息
```

### 6.2 降级链保证

**客服 Agent 三层超时对齐**（v6.11.30）：

```
前端 axios 70s > 后端总预算 60s（Dify 25s + 模型 35s）> 各子环节
```

- Dify 25s 超时 → 走模型降级（model_ai_service ≤35s）
- 模型也失败 → 走本地话术（固定兜底回复）
- **任何路径前端必收回复**，会话记录保留可续上
- 全角色对话流式失败时自动回退非流式接口，同样保证必收回复

### 6.3 Dify 应用清单

Dify 平台共 **9 个应用**，应用名统一标注状态后缀：**4 个【调用中】** / **5 个【废案】**。命名规范固化于 `AGENTS.md` §7.5，`dify-init` 每次运行自动核对写明（幂等）。

| 应用 | 类型 | 状态 |
|------|------|------|
| 粤教客服Agent【调用中】 | Chatflow | ✅ 在用（完整版） |
| 企业员工助手【调用中】 | Agent-chat | ✅ 在用 |
| 留学生智能管家【调用中】 | Agent-chat | ✅ 在用 |
| 智能报告【调用中】 | Chatflow | ✅ 在用 |
| 其余 5 个应用【废案】 | — | 📦 留档（历史版） |

所有应用由 `dify_init.py` 一键初始化完成：创建管理员 → 配模型供应商 → 导入 DSL → 发布 → 写入 app key 共享卷。dify-init 已加固：HTTP 节点旧地址自愈、同名应用确定性去重（key 不漂移）、app key 输出 POSIX 格式（重拉起配置自动就绪）、模型级凭证兼容。

### 6.4 全角色对话流式输出（v6.11.37 / v6.11.39）

| 角色 | 流式端点 |
|------|----------|
| 智能客服 | `POST /ai/customer-service/chat/stream` |
| 学生智能助手 | `POST /student/agent/chat/stream` |
| 企业智能助手 | `POST /employee/agent/chat/stream` |

- 客服 / 学生 / 员工 / 管理层 AI 对话全部走 SSE 流式逐字渲染，**感知延迟 = 首字时间**
- 流式失败自动回退非流式接口，任何路径必收回复
- nginx 反代关闭 `proxy_buffering`，保证逐字下发

### 6.5 客服 Agent 提速（v6.11.37）

- Dify 客服工作流瘦身：每轮 2~3 次串行模型调用 → **1 次**
- 阻塞耗时 13.8~36.4s → **6.6~12.7s**；公网流式首字约 **2.5s**
- 保留 FAQ 秒回 + 三级降级链（Dify → 模型 → 本地话术）

## 八、部署与访问

### 8.1 一键启动

```powershell
# 前置条件：Docker Desktop + WSL2 + 端口 59000/6379/8000/8080/8081 空闲

# 1. 复制环境配置
Copy-Item .env.example .env
Copy-Item dify\docker\.env.example dify\docker\.env

# 2. 配置 Dify 模型凭据（dify\docker\.env 中）
#    - DIFY_MODEL_API_KEY=你的模型 API Key
#    - DIFY_MODEL_BASE_URL=兼容 OpenAI 的模型端点
#    - DIFY_MODEL_NAME=模型名称

# 3. 一键启动（自动完成依赖安装 → 全栈启动（空库自动注入种子）→ 后端健康轮询 → 前端构建 → Dify 初始化 → 内网穿透）
.\start-project.bat
```

启动完成后自动打开浏览器，摘要页显示：

- 本地前端地址：http://localhost:8080
- 本地后端地址：http://localhost:8000
- **公网穿透地址**：免费隧道（localtunnel）每次重启会变化，以 `start-project.bat` 启动输出为准（最近一次为 https://nine-peaches-fetch.loca.lt）
- 访客密码：本机出口 IP（如 113.80.207.199），启动输出中一并显示

### 8.2 手动启动

```powershell
# 仅启动核心业务（不含 Dify）
docker compose up -d mysql redis backend nginx

# 启动 Dify（首次需先启动 dify-init）
docker compose up -d api worker postgres redis sandbox plugin_daemon agent_backend
docker compose run dify-init

# 一键内网穿透（独立入口）
.\start-tunnel.bat
```
